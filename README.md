# GPS 기반 CCTV 자료 관리 도구

> GPS 위치와 공식적으로 제공되는 CCTV 메타데이터를 연계하여, **사용자가 합법적으로 접근할 권한을 가진 영상 자료를 안전하게 기록·관리하기 위한 연구용 프로젝트**입니다.

## 중요 고지

이 저장소는 타인을 몰래 찾아내거나 지속적으로 추적·감시하기 위한 도구가 아닙니다. 얼굴 인식, 번호판 인식, 개인 식별, 비인가 접근, 인증 우회, 서비스 약관을 위반한 수집, 대량 스크래핑은 이 프로젝트의 목표와 허용 범위에 포함되지 않습니다.

개발·검증은 다음 환경으로 제한합니다.

- 본인이 소유하거나 관리하는 CCTV 장비
- 운영 주체의 명시적인 서면 동의를 받은 테스트 환경
- 이용약관과 제공 정책이 허용하는 공식 API·공식 URL·공공데이터
- 관련 법률과 기관 정책을 사전에 검토한 환경

공개되어 있다는 이유만으로 영상을 자유롭게 저장·재배포할 수 있는 것은 아닙니다. 실제 연동 전에는 제공처별 이용약관, 저작권, 영상정보 및 개인정보 보호 규정, 위치정보 관련 규정, 접근 제한, 보관 기간, 삭제 요청 절차를 확인해야 합니다.

## 문제 정의

공공기관이나 운영 주체가 제공하는 CCTV 목록·위치·상태·영상 링크는 서로 다른 형식과 정책으로 제공되는 경우가 많습니다. 이 프로젝트는 먼저 이러한 공개 정보를 표준화하고, 사용자가 지정한 합법적인 범위 안에서 주변 카메라의 **위치·상태·시간대·정책 정보**를 확인할 수 있는 구조를 설계합니다.

영상 자체를 자동 수집하는 기능은 기본값으로 두지 않으며, 허가된 소스에 한해 명시적인 정책 검증과 사용자 확인을 거친 후 제한적으로 다루는 것을 원칙으로 합니다.

## 목표

- 공식 공개 데이터에서 CCTV 카탈로그와 메타데이터를 표준화
- 위치 기반으로 주변 카메라와 제공 정책을 검색
- 영상 수집 전에 권한·이용약관·보존 정책을 검증
- 가능한 경우 영상보다 메타데이터, 이벤트, 저해상도 또는 마스킹 자료를 우선
- 수집·열람·삭제 작업을 감사 로그로 남김
- 보존 기간이 끝난 자료를 자동 삭제하고 삭제 요청을 처리
- 재현 가능한 테스트와 명확한 안전장치를 갖춘 연구용 기반 제공

## 비목표

- 특정 사람을 CCTV에서 찾거나 따라가는 기능
- 얼굴·보행·음성·차량번호 등 생체 또는 식별자 기반 인식
- 타인의 이동 경로를 장기간 축적하거나 프로파일링하는 기능
- 로그인 우회, 접근 제한 회피, 비공식 스트림 추출
- 무단 녹화, 무단 재배포, 데이터 브로커식 수집
- 제공처의 서비스 품질이나 정책을 우회하는 대량 요청

## 허용되는 사용 사례

1. 본인 소유 CCTV에서 장애·사고 시점을 확인하는 개인 기록
2. 명시적 동의를 받은 실험실/교육용 CCTV 테스트
3. 공공기관이 공식적으로 제공하는 카메라 위치·상태·교통 이벤트 메타데이터 조회
4. 제공처가 허용한 범위에서 제한적인 영상 자료 보존 및 삭제 관리
5. 영상 원본 대신 시간, 위치 격자, 카메라 식별자, 상태와 같은 비식별 메타데이터 분석

## 핵심 원칙

### 1. 합법성 우선
소스별 이용약관과 관할 법률을 확인하고, 불확실하면 수집하지 않습니다. 이 프로젝트의 문서는 법률 자문을 대신하지 않습니다.

### 2. 최소 수집
목적 달성에 필요한 최소한의 데이터만 수집합니다. 원본 영상보다 메타데이터나 이벤트를 우선하고, 위치 정밀도와 보존 기간도 최소화합니다.

### 3. 개인 식별 금지
개인 식별, 얼굴·번호판 인식, 임의의 재식별 시도를 구현하거나 추가하지 않습니다. 테스트 데이터는 합성 데이터 또는 적절히 마스킹된 자료를 사용합니다.

### 4. 명시적 권한
공식 API 또는 제공처가 허용한 URL만 사용합니다. 인증 정보는 저장소에 커밋하지 않으며, 접근 권한이 없는 소스는 카탈로그에 등록하지 않습니다.

### 5. 안전한 기본값
수집 기능은 기본 비활성화, 짧은 보존 기간, 낮은 요청 빈도, 허용 목록, 사용자 확인을 기본값으로 합니다.

### 6. 투명성과 감사 가능성
무엇을 언제 어떤 정책으로 조회·저장·삭제했는지 기록하고, 사용자가 데이터와 보존 상태를 확인할 수 있게 합니다.

## 예상 처리 흐름

```text
위치 입력
  -> 위치 정밀도/동의 확인
  -> 공식 CCTV 카탈로그 동기화
  -> 주변 카메라 검색
  -> 제공 정책·권한·보존 조건 검증
  -> 메타데이터 또는 허용된 자료만 선택
  -> 제한된 수집/기록
  -> 암호화 저장 및 접근 통제
  -> 보존 기간 만료·삭제 요청 처리
  -> 감사 로그와 운영 보고
```

현재 저장소에는 위 흐름을 구현한 실행 코드가 없을 수 있습니다. README의 기능 목록과 명령 예시는 계획을 설명하기 위한 것이며, 실제 동작 여부는 구현 상태를 확인해야 합니다.

## 권장 아키텍처

- **Location Input**: 사용자가 직접 입력한 위치 또는 동의된 기기의 위치. 원본 좌표는 필요 시 격자화·정밀도 축소.
- **CCTV Catalog Adapter**: 공공데이터 포털, 기관 API 등 공식 제공처별 어댑터. 제공처 이름, 약관 URL, 갱신 시각, 허용 범위를 함께 저장.
- **Nearby Search**: 거리·시간·운영 상태를 이용한 검색. 검색 결과에는 영상 링크보다 정책과 권한 상태를 우선 표시.
- **Policy & Permission Guard**: 허용 목록, 인증 상태, 이용약관 확인, 요청 제한, 보존 정책 검증.
- **Capture/Metadata Service**: 초기 단계에서는 메타데이터와 이벤트만 저장. 영상 저장은 명시적으로 허용된 소스에서만 활성화.
- **Storage**: 암호화된 저장소와 접근 제어. 원본과 파생 자료를 구분하고 삭제 가능성을 보장.
- **Retention & Deletion**: 보존 기한, 삭제 요청, 계정 삭제, 소스 철회에 따른 삭제 작업.
- **Audit Log**: 조회·수집·열람·내보내기·삭제·정책 변경을 추적하되 로그 자체에도 불필요한 개인정보를 넣지 않음.

## API 및 어댑터 방향

어댑터는 제공처별 차이를 격리하고 공통 인터페이스로 변환합니다.

```text
list_sources() -> 공식 제공처와 정책 정보
sync_cameras(source_id) -> 카메라 메타데이터 갱신
find_nearby(position, radius, time) -> 주변 카메라 후보
check_policy(source_id, action) -> 허용 여부와 근거
record_observation(camera_id, observation) -> 허용된 기록 저장
purge_expired(now) -> 보존 기간 만료 자료 삭제
```

실제 HTTP 요청, 인증 방식, 갱신 주기, 재시도 정책은 각 제공처의 공식 문서와 이용약관을 기준으로 구현해야 합니다. 비공식 스트림 주소를 추측하거나 접근 제한을 회피하는 기능은 추가하지 않습니다.
