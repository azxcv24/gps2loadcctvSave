# ADR-0004: 위치 정밀도와 GPS 공백 처리

- 상태: 채택
- 날짜: 2026-10-26
- 결정자: BOKWANG

## 문맥

FR-02는 경로 좌표의 정밀도를 낮춰 저장하라고 하지만, 정밀도를 낮추면 위치 오차가 커져 통과 시각 계산이 부정확해진다. 초안 데이터 모델은 카메라 좌표도 반올림(`latitude_rounded`)하도록 되어 있었다. 또한 터널·지하차도 등으로 GPS가 끊긴 구간을 어떻게 다룰지 정해지지 않았다.

## 결정

1. **경로 좌표**는 기본 소수점 4자리(위도 약 11m)로 낮춰 저장한다. 반올림으로 생길 수 있는 최대 오차(격자 반대각선, 위도 37도에서 약 7.3m)를 **유효 반경에 더해** 계산이 낙관적으로 되지 않게 한다.
2. **사건 확인 범위(사고 전·후) 밖의 경로 지점은 저장하지 않는다.** 범위 상한은 기본 2시간이다.
3. **카메라 좌표**는 공공 시설 위치로 개인정보가 아니므로 제공처 값을 그대로 저장하고, 대신 `location_uncertainty_m`(카탈로그 좌표 오차)을 함께 기록한다.
4. 유효 반경 = 촬영 반경(기본 100m) + GPS 정확도(없으면 25m) + 반올림 오차 + 카메라 위치 오차.
5. **GPS 공백**(기본 30초 초과 간격)은 직선 보간하지 않는다. 직선 보간은 공백 중 방향을 꺾은 경로의 카메라를 놓친다(테스트로 확인). 대신 공백 전후 관측 속도에 여유 계수(1.3)를 곱한 최대 속도로 "공백 시작점에서 출발해 끝점에 도착할 수 있었던 범위"(시공간 프리즘)를 계산해, 카메라 반경에 들어갈 수 있었던 가장 이른·늦은 시각을 확인 범위로 잡는다. 이런 후보는 신뢰도 "낮음"과 사용자 검토 필요로 표시한다.
6. 경로가 없고 사고 위치만 있으면(`location_only`) 사고 시각 ± (시각 불확실성 + 120초)를 확인 범위로 잡고 신뢰도 "낮음"으로 표시한다.

## 결과와 위험

- 저장 위치 정밀도를 낮추면서도 계산은 보수적으로 유지된다.
- 긴 GPS 공백은 후보가 많아질 수 있다. 모두 "사용자 검토 필요"로 표시되며, 실제 이동 경로를 아는 사용자가 판단한다.
- 기본값(4자리, 100m, 25m, 30초, 1.3배)은 가정값이며 실제 데이터로 조정이 필요하다.

## 재검토 조건

- 실제 차량 GPS 로그(사용자 본인 동의)의 정확도·기록 간격 분포를 확인했을 때
- 제공처 카탈로그가 카메라 방향·화각 정보를 제공할 때(현재는 원형 반경만 사용)
