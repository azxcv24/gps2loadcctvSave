# ADR-0005: GPS 기반 실시간 자동 녹화로 전환

- 상태: 승인(저장소 소유자 요청, 2026-10-27)
- 날짜: 2026-10-27
- 결정자: 저장소 소유자
- 대체: ADR-0003의 "영상은 수집하지 않는다" 결정을 대체한다. 정책 검증의 '실패 시 거부' 원칙은 유지한다.

## 문맥

소유자가 목표를 다음과 같이 명확히 했다. 사용자는 Traccar 앱 등으로 GPS만 보내고, 시스템이
사용자(또는 사용자 차량)가 지나가는 공공 CCTV를 **알아서** 확인해, 지나가는 동안(+앞뒤 1~2초)의 영상을
**완전 자동으로** 저장해야 한다. 사고 후 보존 요청만으로는 원본이 이미 삭제됐거나 절차가 늦을 수 있다.

## 결정

1. `gps2cctv serve` 하나로 GPS 수신 → 카메라 녹화 대기 → 통과 구간 저장을 자동으로 한다.
2. **GPS 수신**은 Traccar의 OsmAnd 프로토콜(쿼리·JSON·서버 전달 형식)을 그대로 받는다.
   등록된 기기 식별자만 받는다.
3. **카메라**는 국가교통정보센터 ITS CCTV 오픈 API(실시간 HLS 주소 제공)와, 본인 소유 카메라 목록
   파일(`owned` 환경)에서 가져온다. 전국 목록을 받지 않고 기기 주변 타일만 갱신한다.
4. **미리 녹화 대기**: 진행 방향 앞쪽, 도착 예상 60초 이내 카메라의 스트림을 디스크 링 버퍼로 받는다.
   공공 CCTV 스트림은 실제보다 몇~수십 초 늦게 나오므로 통과 직전에 시작해도 충분하다.
5. **통과 판정**은 오프라인 후보 계산과 같은 `compute_passages`(유효 반경, GPS 공백 프리즘)를 쓴다.
   영상 속 대상은 식별하지 않는다.
6. **저장 구간** = `[진입 − pre_seconds, 이탈 + post_seconds]`(기본 2초) ± 스트림 시각 추정 오차.
   - `#EXT-X-PROGRAM-DATE-TIME` 이 있으면 그 시각(오차 ±1초)
   - 없으면 재생목록에 나타난 시각 − 추정 지연(오차 ±4~6.5초)
7. **저장 형식**: 세그먼트 바이트를 그대로 이은 원본(SHA-256) + 정확히 자른 보기용 mp4 + 근거 JSON.
8. **사고 의심 이벤트**(급정거·SOS·수동 표시)는 앞뒤 클립을 보호하고 사건·보존 요청 후보를 자동 생성한다.
9. **정책 검증 유지**: 설정 파일에 적은 소스는 소유자 승인으로 보고 정책 검토 기록을 자동 갱신한다
   (유효 2일, 12시간마다 갱신). 소스를 비활성화하면 즉시 녹화가 멈춘다. 영상 녹화는 `video` 기능이 있고
   정책 검토에서 `media_capture` 를 허용한 소스만 가능하다.
10. **보존·용량**: 보호하지 않은 클립과 위치 기록은 기본 14일 뒤 삭제, 전체 20GB를 넘으면 오래된 것부터 삭제.

## 계속 하지 않는 것

- 얼굴·번호판·차량 인식, 영상 속 대상 식별, 등록하지 않은 사람·기기의 위치 추적
- 로그인 우회, 접근 제한 회피, 비공식 스트림 주소 추측

## 결과와 위험

- 스트림에 시각 태그가 없으면 앞뒤 여유가 2초보다 길어진다(차량이 잘리지 않게 하기 위함).
  카메라별 `stream_delay_seconds` 를 맞추거나 `include_time_uncertainty = false` 로 줄일 수 있다.
- ITS API의 파라미터·응답 형식은 공개 검색 결과로 확인했고 공식 문서를 직접 열람하지는 못했다.
  JSON·XML을 모두 받도록 했으며, 실제 키로 처음 실행할 때 로그를 확인해야 한다.
- 공공 데이터 이용 조건(공공누리 유형 등)은 소유자가 확인한다. 저장한 클립은 개인 증거 보관 목적으로만 쓴다.

## 재검토 조건

- ITS 실제 스트림에 시각 태그가 있는지, 실제 지연이 얼마인지 확인됐을 때(기본값 조정)
- 다른 지자체 CCTV 오픈 API(예: 경기도 교통정보) 연동을 추가할 때
