# ADR-0003: 메타데이터·보존 요청 초안 우선, 정책 검증은 실패 시 거부

- 상태: 제안
- 날짜: 2026-10-26
- 결정자: (저장소 소유자 승인 필요)

## 문맥

PLAN의 결정 후보 "상시 영상 버퍼를 허용할지, 메타데이터만 기록할지"와 "제공처 보존 요청과 직접 수집의 우선순위"가 열려 있었다. 또한 "공식 소스만 등록"(FR-03)을 프로그램이 어떻게 판단할지 정해지지 않았다.

## 결정

1. **영상은 수집하지 않는다.** `media_capture` 행위는 정책 검토로도 허용할 수 없고, 정책 검증에서 항상 거부한다. 상시 영상 버퍼도 두지 않는다.
2. **보존 요청은 초안만 만든다.** 프로그램이 제공처에 직접 제출하지 않는다. 사용자가 공식 절차로 제출한 뒤 상태·접수번호만 기록한다. 요청인 연락처는 저장하지 않고 초안에 "(직접 기재)"로 남긴다.
3. **'공식 소스' 판단은 사람 + 허용 목록**으로 한다.
   - 실제(production) 소스는 HTTPS이고 설정의 `allowed_hosts`에 있는 호스트만 등록할 수 있다. 기본 허용 목록은 비어 있다.
   - 합성(synthetic) 소스는 실제 요청이 불가능한 예약 도메인(`.invalid`, `.test`, `.example`)만 쓸 수 있다.
   - 등록 뒤에도 사람이 약관·절차를 검토한 **정책 검토 기록**(허용 행위, 유효 기간)이 있어야 동기화·조회·요청 준비가 가능하다.
4. **실패 시 거부(fail closed)**: 검토 기록 없음·만료·미래 시각·허용하지 않은 행위·소스 정보(엔드포인트·약관·기능) 변경 후 미재검토·비활성 소스는 모두 거부하고 감사 로그에 사유 코드를 남긴다.
5. 신뢰도가 낮거나 범위가 넓은 후보로 요청 초안을 만들려면 `--reviewed`로 사용자가 직접 검토했음을 밝혀야 한다.

## 결과와 위험

- 영상·개인정보를 다루지 않으므로 MVP의 법적·보안 위험이 작다.
- 실제 사용 가치는 제공처 보존 절차를 얼마나 정확히 안내하느냐에 달려 있다(M2에서 첫 제공처 검토 필요).
- 소스 비활성화(`source disable`)가 비상 중단 수단이다.

## 재검토 조건

- 특정 제공처가 공식 API로 보존 요청 접수를 지원하고, 약관이 자동 제출을 허용할 때
- M3에서 허용된 소스에 한해 이벤트·스틸 수집을 검토할 때
